# Self-Management V3.5: Calendar-first workload planning

Status: **in development on feature/v3.5-calendar-scheduling; not deployed**.

## Agreed user workflow
- TODAY defaults to calendar schedule, topped by a large **NOW / UP NEXT** indication of the next action and planned duration.
- Day, workweek, and month views. Existing action list remains accessible.
- Actions support total estimated effort, remaining effort, due date, and zero or more independently movable scheduled work blocks.
- **Needs Scheduling** contains unscheduled effort for incomplete actions due in the next 30 days, plus overdue and high-priority work; partially scheduled actions still appear with remaining unscheduled minutes.
- Actions may be created without a time slot.
- Drag actions onto the calendar; split larger work across blocks.
- At the end of a block, ask “Did you complete this action?” A “No” prompts for remaining effort, leaving the parent action open and returning unscheduled minutes to the queue. Ending a block never silently completes the action.
- Auto-Schedule fills the earliest suitable openings between fixed commitments, without reserving default buffer time. Short gaps can fit short tasks. Preserve manually scheduled work.
- Moving a block supports manual rescheduling, suggested placement/Make Room, Move to Next Week, and Unschedule. Changes must never delete the parent task.
- Outlook meetings are immutable. Meetings displace *automatic* action blocks, not manual ones. Report manual conflicts for user resolution.
- Meeting preparation is optional and protected when enabled. If required prep cannot fit, warn.
- After sync, tell the user which auto blocks moved, which items remain unscheduled, and whether due dates are at risk; offer undo of local scheduling changes.
- Existing save behavior (disabled SAVING state, no full-page navigation/reload) must remain intact.
- Small laptop display optimization comes later.

## Implementation boundaries
1. Scheduling calculations in `scheduler-v35.js` are pure and do not mutate the live backend.
2. Add persistence for scheduled blocks and effort in Apps Script / Google Sheets before wiring live UI. Include idempotent write IDs and preserve recurrence behavior.
3. Build the TODAY calendar and Needs Scheduling UI and test action creation, editing, unscheduling, and completion without page reload.
4. Add Outlook *read-only* meeting sync subject to organization permissions. Never claim availability or sync success until authorized and tested.
5. Enable automatic conflict reflow only after preserving manually scheduled work and protecting prep time.
6. Test with realistic overlapping meetings, multi-day projects, short gaps, missed deadlines, recurring actions, daylight-saving transitions, offline/network failures, and duplicate-save attempts.

## Outstanding design choice
Minimum split duration may be configurable (initial candidate 30 minutes); user has not selected it. Do not force an arbitrary preference.
